# Update-Bun Implementation Plan

## Overview

Add a single `Update-Bun` PowerShell function to `Microsoft.PowerShell_profile.ps1` that runs `bun update -g` to update all globally installed bun packages, and integrate it into the existing `Update-All` umbrella function. The change follows the exact pattern of the existing `Update-Winget` function — single-command body, 4-space indent, opening brace on the same line, no error handling.

## Requirements

- `Update-Bun` SHALL execute `bun update -g`
- `Update-Bun` SHALL be callable standalone from the PowerShell prompt
- `Update-All` SHALL call `Update-Bun` after `Update-Scoop` and before `Update-Winget`
- Function definition SHALL be placed after `Update-Scoop` (after line 27) and before `Set-Shell-Proxy` (line 29)
- Error propagation SHALL follow the existing bare convention (no try/catch, no guards)
- 4-space body indentation, opening brace on the function signature line, closing brace on its own line

## Current State Analysis

`Microsoft.PowerShell_profile.ps1` (47 lines, 18 functions) defines a cluster of update functions:

- **`Update-All`** (line 13): umbrella — calls `Update-Scoop`, then `Update-Winget`
- **`Update-Winget`** (line 19): `winget update --all`
- **`Update-Scoop`** (line 23): three-command function (`scoop update`, `scoop update *`, `scoop cleanup *`)

The `Update-Bun` function and its call in `Update-All` are both missing. The existing pattern is well-established and consistent across all 18 functions.

### Key Discoveries

- `Microsoft.PowerShell_profile.ps1:19-21` — `Update-Winget` is the exact pattern template (single-command body, same brace/indent style)
- `Microsoft.PowerShell_profile.ps1:13-16` — `Update-All` insertion site: line 14 (`Update-Scoop`) → **new line for `Update-Bun`** → line 15 (`Update-Winget`)
- `Microsoft.PowerShell_profile.ps1:27-29` — Function definition insertion site: after line 27 (`}` closing `Update-Scoop`), before line 29 (blank line preceding `Set-Shell-Proxy`)
- All profile functions use 4-space body indent, opening brace on the same line, closing brace on its own line, one blank line separator between functions
- PowerShell resolves function calls at runtime, not definition time — lexical ordering is cosmetic
- No error handling convention exists: all 18 functions propagate errors raw

## Desired End State

```powershell
# Standalone usage:
PS> Update-Bun
# Output: bun update -g runs, shows updated packages

# Via umbrella:
PS> Update-All
# Calls Update-Scoop → Update-Bun → Update-Winget
```

## What We're NOT Doing

- Not updating bun itself (handled by Scoop via `Update-Scoop`)
- Not adding error handling guards (`Get-Command bun`, try/catch, `$LASTEXITCODE` checks) — per developer decision, follows the bare convention of all existing functions
- Not adding test files (no test harness exists for this profile)
- Not installing or uninstalling bun global packages
- Not implementing `bunx`-based update mechanisms

## Decisions

### Function body: single-command `bun update -g`
**Ambiguity**: What command should `Update-Bun` run?
**Explored**: `bun update -g` — confirmed with developer during discovery. Analogous to `npm update -g`.
**Decision**: `bun update -g`. No alternatives considered — developer-verified behavior.

### Placement: after Update-Scoop
**Ambiguity**: Where should the function definition go in the file?
**Explored**: After `Update-Scoop` (grouping tool-specific updaters) vs. before `Update-Scoop` (alphabetical).
**Decision**: After `Update-Scoop` (line 27 closing brace), before `Set-Shell-Proxy`. Developer-requested placement.

### Integration: both standalone + Update-All
**Ambiguity**: Should `Update-Bun` be standalone only, or also called from `Update-All`?
**Explored**: Both — the "update everything" intent of `Update-All` should include bun global packages.
**Decision**: Both. Call `Update-Bun` between `Update-Scoop` and `Update-Winget` inside `Update-All`.

### Error handling: follow bare convention
**Ambiguity**: Should `Update-Bun` add a `Get-Command bun` guard or follow the existing no-error-handling convention?
**Explored**: _All_ 18 profile functions propagate errors raw. Only `gb` checks `$LASTEXITCODE`, and it only writes a warning (no early return).
**Decision**: Follow convention — no guards. If `bun` is not on PATH or `bun update -g` fails, the error propagates visibly to the user.
