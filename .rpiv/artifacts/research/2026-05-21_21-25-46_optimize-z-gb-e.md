# Research: Optimizing z, gb, e PowerShell Functions

## Research Question
分析 `Microsoft.PowerShell_profile.ps1` 中三个导航函数 (`z`, `gb`, `e`) 的优化空间，在保持现有结构（不提取辅助函数）的前提下，给出最小侵入性改进方案。

## Summary
三个函数 (`z:102`, `gb:111`, `e:120`) 共享完全相同的 `if ($args.Count -eq 0)` 分支结构，路径硬编码 `$env:USERPROFILE\workspace` 于三处。经分析确定三项优化：

1. **统一错误处理** — 每个函数的 `else` 分支加 `Test-Path` 守卫 + 空字符串 `Trim()` 兜底 + 回退到 workspace，`gb` 额外加 `$LASTEXITCODE` 检查
2. **`gb` 新增 `-w 0`** — `wt` 调用加上 `-w 0`，确保在当前窗口新标签页打开 Git Bash
3. **保持现有结构** — 不提取辅助函数，不下沉 `Get-NavTarget`，各自保持独立

## Detailed Findings

### 1. 当前实现分析 (`Microsoft.PowerShell_profile.ps1:102-127`)

#### `z` — 快速目录跳转 (lines 102-109)
```powershell
function z {
    if ($args.Count -eq 0) {
        Set-Location $env:USERPROFILE\workspace
    }
    else {
        Set-Location $args[0]
    }
}
```
- 无参时跳转到 workspace 根目录
- 有参时将参数直接传给 `Set-Location`，**无 `Test-Path` 校验，无 `-ErrorAction`**
- 空字符串参数 (`z `) 绕过 `$args.Count -eq 0` 守卫，进入 `else` 分支后报错

#### `gb` — 启动 Git Bash (lines 111-118)
```powershell
function gb {
    if ($args.Count -eq 0) {
        wt -p "Git Bash" -d $env:USERPROFILE\workspace
    }
    else {
        wt -p "Git Bash" -d $args[0]
    }
}
```
- 无参时默认在 workspace 打开 Windows Terminal → Git Bash
- 有参时 `wt.exe -d` 接收目录参数
- **`wt` 是外部程序**，不能用 `-ErrorAction` 抑制错误
- 无效路径触发 Windows 错误对话框（不是红色 PowerShell 错误文本）
- 空字符串参数 (`gb `) **静默退回到当前目录**（最危险的边缘情况 — 无任何提示）

#### `e` — 打开资源管理器 (lines 120-127)
```powershell
function e {
    if ($args.Count -eq 0) {
        Invoke-Item $env:USERPROFILE\workspace
    }
    else {
        Invoke-Item $args[0]
    }
}
```
- 同 `z` 模式，使用 `Invoke-Item` 而非 `Set-Location`
- **无 `Test-Path` 校验，无 `-ErrorAction`**

### 2. 错误处理缺口 (`z:102-127`, 全 profile)

**全 profile 缺陷统计**: 18 个函数中零处使用 `try/catch`、`-ErrorAction`、`-ErrorVariable`、`Test-Path` 或 `$?`。

但同一作者的 `restore-scoop.ps1:10` 使用了 `try { Invoke-Expression $_ } catch { Write-Warning }`，证明作者熟悉错误处理机制。

各函数的失败模式：

| 函数 | 无效路径行为 | 可否用 `-ErrorAction` |
|------|-------------|---------------------|
| `z` | 红色错误文本 `Set-Location: Cannot find path` | ✅ 是 (cmdlet) |
| `gb` | Windows 对话框 + stderr 文本 | ❌ 否 (外部程序) |
| `e` | 红色错误文本 `Invoke-Item: Cannot find path` | ✅ 是 (cmdlet) |

### 3. 空字符串边界情况 (`z:107`, `gb:116`, `e:125`)

当用户输入 `z `（命令名后跟空格+回车），PowerShell 解析器生成 `$args = @("")`：
- `$args.Count` 为 1，`-eq 0` 分支**不被命中**
- `else` 分支执行 `Set-Location ""` / `wt -d ""` / `Invoke-Item ""`
- `z` 和 `e` 报错，`gb` 静默退回到 CWD

## Implementation: Final Edits Applied

### Fix 1: Test-Path guards + empty-string fallback (z, e)

```powershell
# z: lines 102-117
function z {
    if ($args.Count -eq 0) {
        Set-Location $env:USERPROFILE\workspace
    }
    else {
        $target = $args[0].Trim()
        if (-not $target) {
            Set-Location $env:USERPROFILE\workspace       # 空字符串→回退到 workspace
        }
        elseif (Test-Path $target -PathType Container) {
            Set-Location $target
        }
        else {
            Write-Warning "Directory not found: $target"
        }
    }
}

# e: same pattern, Invoke-Item + Test-Path (不带 -PathType Container)
```

### Fix 2: Test-Path guard + empty-string fallback + LASTEXITCODE check (gb)

```powershell
function gb {
    if ($args.Count -eq 0) {
        wt -w 0 -p "Git Bash" -d $env:USERPROFILE\workspace
    }
    else {
        $target = $args[0].Trim()
        if (-not $target) {
            wt -w 0 -p "Git Bash" -d $env:USERPROFILE\workspace
        }
        elseif (Test-Path $target -PathType Container) {
            wt -w 0 -p "Git Bash" -d $target
            if ($LASTEXITCODE -ne 0) {
                Write-Warning "wt exited with code $LASTEXITCODE for: $target"
            }
        }
        else {
            Write-Warning "Directory not found: $target"
        }
    }
}
```

### Fix 3: `-w 0` added to all three wt calls

`-w 0` ensures Git Bash opens in the current Windows Terminal window as a new tab, rather than spawning a new window.

### Removed: Tab completion (Register-ArgumentCompleter)

Initially added but subsequently removed per user request.
