# Research: Update-Bun

## Research Question
Add an `Update-Bun` PowerShell function to `Microsoft.PowerShell_profile.ps1` that runs `bun update -g` to update all globally installed bun packages, and hook it into the existing `Update-All` function alongside `Update-Scoop` and `Update-Winget`.

## Summary
The change is a clean single-file, dual-insert edit to `Microsoft.PowerShell_profile.ps1` (47 lines, 18 functions). Two insertions needed: (1) a new `function Update-Bun { bun update -g }` block inserted after `Update-Scoop` (line 28) and before `Set-Shell-Proxy` (line 33), and (2) an `Update-Bun` call inserted inside `Update-All` (line 14) between `Update-Scoop` and `Update-Winget`. No deletions, no refactoring. The error propagation model (native .exe → `$LASTEXITCODE` → stderr visible) is identical to existing `Update-Winget` and `Update-Scoop` — no error handling wrapper needed or desired. A precedent `Update-Pnpm` existed previously with the same pattern and was removed after ~5 weeks; the developer confirmed bun is long-term.

## Detailed Findings

### Existing Profile Structure
`Microsoft.PowerShell_profile.ps1:1-47` defines 18 functions at script scope. The relevant update cluster is:

- **`Update-All`** (line 14): umbrella function chaining `Update-Scoop` then `Update-Winget`
- **`Update-Winget`** (line 19): single-command function, `winget update --all`
- **`Update-Scoop`** (line 23): three-command function, `scoop update; scoop update *; scoop cleanup *`
- **`Set-Shell-Proxy`** (line 33): next function after `Update-Scoop`

The call order in `Update-All` (`Update-Scoop` → `Update-Winget`) does NOT match file definition order (`Update-Winget` at line 19 comes before `Update-Scoop` at line 23). This is a pre-existing inconsistency and proves PowerShell resolves function calls at runtime, not definition-time.

### Insertion Points

**Insertion 1 — `Update-Bun` function definition** (after `Microsoft.PowerShell_profile.ps1:28`):
```
line 28: }                               # closing brace of Update-Scoop
line 29:                                  # blank line (separator)
--- INSERT function Update-Bun { ---
---          bun update -g               # 4-space indent
---      }                               # blank line after
line 30: function Set-Shell-Proxy {      # shifts down
```
The blank line at line 29 is part of the one-blank-line separator pattern used between all function definitions. The insertion replaces it with the 3-line function block + a new blank line separator before `Set-Shell-Proxy`.

**Insertion 2 — `Update-Bun` call in `Update-All`** (new line 16):
```
function Update-All {
    Update-Scoop
    Update-Bun          ← NEW
    Update-Winget
}
```

### Style Mapping
All functions in the file use 4-space body indentation. The `Update-Bun` function matches `Update-Winget`'s exact shape:
- Opening brace on the `function` line
- Single command, 4-space indented
- Closing brace on its own line
- No semicolons (consistent with `Update-Winget` and `Update-Scoop`; only `Set-Shell-Proxy` uses them)

### Error Propagation
`bun` is a native executable (`bun.exe`). PowerShell's native command invocation model:
1. Spawns `bun.exe` with `["update", "-g"]`
2. stdout/stderr pass through to the console unmodified
3. Exit code sets `$LASTEXITCODE` automatically
4. `$?` set to `$LASTEXITCODE -eq 0` (not checked by any existing function)

The `Update-All` chain uses newline-separated statements (equivalent to `;`), which do NOT short-circuit on error — consistent with existing `Update-Scoop`/`Update-Winget` behavior. If `Update-Bun` fails, `Update-Winget` still runs.

The only `$LASTEXITCODE` check in the entire file is at `gb` (line 125), and it only writes a warning — no early return, no error suppression.

### Infrastructure Wiring

## Architecture Insights
- **Lexical ordering is cosmetic, not functional**: PowerShell resolves function calls at invocation time (not definition time). `Update-Winget` is defined before `Update-Scoop` in the file, but called after in `Update-All` — this works fine.
- **No error handling convention**: All 18 functions propagate errors raw. The `gb` function is the only exception (writes a warning on failure but does not stop execution). The developer confirmed `Update-Bun` should follow the bare convention.
- **4-space indent is universal**: Every function body uses 4-space indentation. No tabs, no 2-space, no mixed styles.
- **Previous sibling function removed**: `Update-Pnpm` (same pattern, `pnpm update -g`) existed from Oct–Dec 2025 and was removed. Developer confirmed bun is long-term.
- **Wrong-command precedent**: `Reset-Npm-Proxy` used `npm config get` instead of `npm config delete` for 3 months (fix commit `4cfb123`). The developer has already verified `bun update -g` behavior.
