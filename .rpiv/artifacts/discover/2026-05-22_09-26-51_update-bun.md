# FRD: Update-Bun

## Summary
Add an `Update-Bun` PowerShell function to `Microsoft.PowerShell_profile.ps1` that runs `bun update -g` to update all globally installed bun packages, and hook it into the existing `Update-All` function alongside `Update-Scoop` and `Update-Winget`.

## Problem & Intent
The user has globally-installed bun packages that need periodic updates. The existing profile already has `Update-All` as a one-stop command to update everything (Scoop packages, Winget packages), but bun's global packages are not covered. The user wants parity: a dedicated `Update-Bun` function that works standalone and is also called from `Update-All`.

The user explicitly clarified: this is about updating bun's *global packages* (analogous to `npm update -g`), **not** updating bun itself — bun is already managed via Scoop (`scoop update bun`).

## Goals
- Add a standalone `Update-Bun` function that runs `bun update -g`
- Integrate `Update-Bun` into the existing `Update-All` function
- Follow the same naming convention and code style as existing `Update-Scoop` / `Update-Winget`

## Non-Goals
- Updating bun itself (handled by Scoop via `Update-Scoop`)
- Installing or uninstalling bun global packages
- `bunx`-based update mechanisms

## Functional Requirements
1. `Update-Bun` SHALL execute `bun update -g` to update all globally installed bun packages
2. `Update-Bun` SHALL be a standalone function callable from the PowerShell prompt
3. `Update-All` SHALL call `Update-Bun` after `Update-Scoop`

## Non-Functional Requirements
- **Performance**: `bun update -g` runs quickly — no performance concern
- **Security**: No elevated privileges needed; bun global packages are per-user by default
- **UX / Accessibility**: Consistent naming (`Update-Bun`), consistent placement alongside sibling update functions
- **Reliability**: If bun is not installed or `bun update -g` fails, the error propagates visibly to the user (consistent with existing behavior of `Update-Scoop` / `Update-Winget`)

## Constraints & Assumptions
- **Platform**: Windows — the profile runs under PowerShell 5.1+ / pwsh
- **Bun availability**: `bun` is expected to be on `$env:PATH` (it is — v1.3.14 confirmed)
- **Existing pattern**: The new function follows the exact shape of `function Update-Winget { winget update --all }` and `function Update-Scoop { ... }`
- **No error handling wrapper**: Like the existing functions, if `bun update -g` fails, the terminal shows the error directly — no try/catch, no silent swallowing

## Acceptance Criteria
- [ ] Running `Update-Bun` in PowerShell executes `bun update -g` and shows output
- [ ] Running `Update-All` invokes `Update-Bun` (visible in the output stream)
- [ ] The function definition is placed right after `Update-Scoop` and before `Update-All` in `Microsoft.PowerShell_profile.ps1`
- [ ] The function name follows the `Verb-Noun` convention matching `Update-Scoop`, `Update-Winget`

## Recommended Approach
Add a single function `Update-Bun` (`bun update -g`) to `Microsoft.PowerShell_profile.ps1`, placed right after the `Update-Scoop` function block, and add the call `Update-Bun` inside `Update-All`'s body.

## Decisions

### Command choice — `bun update -g`
**Question**: When you say "更新被 bun 安装的全局包" — what command do you envision doing that?
**Recommended**: `bun update -g` (Recommended)
**Chosen**: `bun update -g`
**Rationale**: Closest analog to `npm update -g`, one-command simplicity, directly updates all globally installed packages.

### Update-All integration
**Question**: Should Update-Bun be called from Update-All (alongside Update-Scoop and Update-Winget), or should it be standalone only?
**Recommended**: Both — standalone + in Update-All (Recommended)
**Chosen**: Both
**Rationale**: Consistent with the "update everything" intent of `Update-All`. No reason to exclude bun global packages when Scoop and Winget packages are included.

### Placement in file
**Question**: Where would you like Update-Bun to sit relative to the other Update-* functions?
**Recommended**: After Update-Scoop (Recommended)
**Chosen**: After Update-Scoop
**Rationale**: Naturally groups tool-specific updaters together — `Update-Scoop`, `Update-Bun`, then `Update-Winget` in `Update-All`.
